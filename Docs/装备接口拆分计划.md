# 装备接口拆分计划

## 背景

当前物品体系存在以下问题：

1. **`AItemBase` 已声明 `Equip()` / `UnEquip()` 虚函数，但均为空壳**，`AWeaponBase` 也未重写它们。装备逻辑实际上未落地。
2. **`IUseableItem` 接口仅负责输入驱动的"使用"行为**（PrimaryUse / SecondaryUse），语义为"这个物品能响应玩家按键"。但装备/卸下是物品生命周期的前置步骤，调用方和时机完全不同。
3. **方案讨论结论**：不把 Equip 合并进 `IUseableItem`，而是新增独立的 `IEquippableItem` 接口。理由——两个职责的调用方、调用频率、生命周期均不同。

## 目标

- 所有**可装备物品**（武器、防具、饰品等）实现 `IEquippableItem` 接口。
- 装备/卸下逻辑从 `AItemBase` 基类中移除，避免"药水也强制有 Equip"的语义污染。
- 和已有的 `IUseableItem` 保持一致的设计范式：`UINTERFACE(MinimalAPI)` + `IInterface` 纯虚类 + `BlueprintNativeEvent`。

## 影响范围

```
新增：
  Source/BearSurvior/Public/Equippable/IEquippableItem.h
  Source/BearSurvior/Private/Equippable/IEquippableItem.cpp

修改：
  Source/BearSurvior/Public/ItemBase.h          ← 移除 Equip/UnEquip 声明
  Source/BearSurvior/Private/ItemBase.cpp        ← 移除 Equip/UnEquip 实现
  Source/BearSurvior/Public/Weapon/WeaponBase.h  ← 增加 IEquippableItem 继承 + _Implementation 声明
  Source/BearSurvior/Private/WeaponBase.cpp      ← 实现 Equip_Implementation / UnEquip_Implementation
```

## 实现步骤

### 第 1 步：创建 `IEquippableItem` 接口

**头文件** `Source/BearSurvior/Public/Equippable/IEquippableItem.h`：

```cpp
// 可装备物品接口。定义装备与卸下的生命周期入口，供武器、防具等可装备物品实现。
// 装备/卸下仅负责附加到角色骨骼、隐藏世界网格等设置；使用阶段由 IUseableItem 独立管理。

#pragma once

#include "CoreMinimal.h"
#include "UObject/Interface.h"
#include "IEquippableItem.generated.h"

UINTERFACE(MinimalAPI)
class UEquippableItem : public UInterface
{
	GENERATED_BODY()
};

class BEARSURVIOR_API IEquippableItem
{
	GENERATED_BODY()

public:
	// 装备物品：将此物品附加到角色骨骼并激活装备效果。
	UFUNCTION(BlueprintCallable, BlueprintNativeEvent, Category = "Default")
	void Equip(AActor* CharacterOwner);

	// 卸下物品：从角色骨骼分离并停用装备效果。
	UFUNCTION(BlueprintCallable, BlueprintNativeEvent, Category = "Default")
	void UnEquip(AActor* CharacterOwner);
};
```

**实现文件** `Source/BearSurvior/Private/Equippable/IEquippableItem.cpp`：

```cpp
// 可装备物品接口实现文件。接口本身为纯虚定义，无默认实现逻辑。

#include "Equippable/IEquippableItem.h"
```

### 第 2 步：从 `AItemBase` 移除 `Equip` / `UnEquip`

删除 `ItemBase.h` 中的 `Equip()`、`UnEquip()` 声明，以及 `ItemBase.cpp` 中的实现。`PickUp()` 和 `Drop()` 保留不动——拾取/丢弃是所有物品的公共行为，而装备/卸下不是。

### 第 3 步：`AWeaponBase` 实现 `IEquippableItem`

`WeaponBase.h` 修改多继承：

```cpp
// 旧
class BEARSURVIOR_API AWeaponBase : public AItemBase, public IUseableItem
// 新
class BEARSURVIOR_API AWeaponBase : public AItemBase, public IUseableItem, public IEquippableItem
```

`WeaponBase.h` 新增声明：

```cpp
virtual void Equip_Implementation(AActor* CharacterOwner) override;
virtual void UnEquip_Implementation(AActor* CharacterOwner) override;
```

`WeaponBase.cpp` 新增实现：

```cpp
void AWeaponBase::Equip_Implementation(AActor* CharacterOwner)
{
	// 附加到角色骨骼
	// 隐藏世界中的 ItemMesh
	// 初始化武器状态（耐久、弹匣等）
}

void AWeaponBase::UnEquip_Implementation(AActor* CharacterOwner)
{
	// 从角色骨骼分离
	// 显示世界中的 ItemMesh 或直接隐藏
	// 清理武器状态（停止攻击、重置瞄准等）
}
```

### 第 4 步：角色侧对接（后续）

当 `ABearSurviorCharacter` 增加装备管理逻辑时，统一使用：

```cpp
// 装备
if (Item->Implements<UEquippableItem>())
{
    IEquippableItem::Execute_Equip(Item, CharacterOwner);
    CurrentHeldItem = Item;
}

// 卸下
if (CurrentHeldItem->Implements<UEquippableItem>())
    IEquippableItem::Execute_UnEquip(CurrentHeldItem, CharacterOwner);
CurrentHeldItem = nullptr;
```

## 最终类层次

```
AItemBase                                            ← PickUp / Drop（公共）
  │
  ├── AWeaponBase : IUseableItem, IEquippableItem    ← 武器：可装备 + 可使用
  │
  │  (未来)
  ├── AConsumable : IUseableItem                     ← 消耗品：只能使用，不能装备
  ├── AArmor : IEquippableItem                       ← 防具：只能装备，不能主动使用
  └── AQuestItem : (none)                            ← 任务物品：不可使用，不可装备
```

## 验证方式

1. UBT 编译通过（`Build.bat BearSurviorEditor Win64 Development`）。
2. 编辑器中，`AWeaponBase` 蓝图子类应能在 Class Settings 中看到 `EquippableItem` 接口已实现。
3. 蓝图或 C++ 调用 `Execute_Equip` / `Execute_UnEquip` 能正常进入 `AWeaponBase` 实现。
